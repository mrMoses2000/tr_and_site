### Запрошено этапом
```text
- Изоляция состояния между книгами: чтение одной и той же страницы двух книг не смешивает прогресс, закладки и карточки.

```

```text
1. V2 Contracts & Types:
   - В app/src/domain/v2/types.ts добавлены BookCitationMetadata и ResearchCardV2 с полями bookSlug, releaseId, sourceAnchor, citationSnapshot.
   - В app/src/domain/types.ts расширен интерфейс ResearchCard с сохранением обратной совместимости.

3. Dynamic Citation Service (app/src/domain/citation.ts):

   - useReader.ts обновлён: изолированное хранение закладок, карточек и позиции для каждой книги; реакция на hashchange (Back/Forward).
```

## 7. Архитектурные решения

| Решение | Альтернативы | Почему выбрано | Положительное следствие | Отрицательное следствие |
|---|---|---|---|---|
| Хранение состояния по ключам `logos.reader.book.<slug>.*` | Хранение всех книг в одном объекте JSON | Атомарные операции per-book, отсутствие lock contention и оверхеда сериализации всех книг | Чтение/запись данных книги изолированы | Несколько ключей в localStorage |
| Маршрутизация через URL hash `#book=<slug>&page=<p>` | HTML5 History API pushState с путями `/book/...` | Приложение работает как статический клиент на локальном origin без необходимости настройки fallback rewrites на Caddy/Nginx | Совместимость с любым статическим хостингом | Длина URL hash при дополнительных параметрах |
| Двухфазная миграция данных с `logos.reader.legacy.unassigned` | Удаление старых ключей сразу или перезапись первой попавшейся книгой | Правило Section 11.2: миграция в `schreiner-ntt` только при наличии доказательств книги | Неоднозначные заметки пользователя не теряются | Требуется UI для выбора книги для неназначенных карточек |
