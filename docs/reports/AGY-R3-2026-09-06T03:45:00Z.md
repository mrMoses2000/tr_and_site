## 1. Problem Addressed
In previous phases:
1. **Lost Diagrams**: InDesign vector drawings (e.g. 43 drawings on page 45, 48 on page 50, 25 on page 430) contain zero raster images (`page.get_image_info()` returns empty). The extractor ignored vector drawings and emitted nothing for diagrams.
2. **Diagram Fragmentation Leaked into Body Prose**: Text labels, structural letters (`Т`, `Е`, `К`, `С`, `Т`), and grammatical syntax tags (`Сп`, `в похвалу`, `славы`, `благодати Своей`) were emitted as independent `ParagraphBlock`s. The frontend reader's short-string heuristic erroneously converted these fragments into `<h2>` headings.
3. **Inverted Reading Order (Page 50)**: PyMuPDF's raw block list placed the bottom prose (`экзегезы. Во-вторых...`) at raw block index 2, prior to the top diagram elements (raw blocks 3-15), violating the visual reading order of the printed page.

## 2. Implementation Changes
1. [`ingestion_service/ast/builder.py`](file:///home/moses/tr_and_site/ingestion_service/ast/builder.py):
   - Implemented `_extract_vector_diagrams`:
     - Identifies diagram caption blocks matching `^(?:Рис\.|Рисунок)\s*\d+`.
     - Determines diagram vertical bounding boxes based on full-width prose boundaries or header cutoffs.
     - Encloses all diagram blocks, labels, and vector annotations into structured `FigureBlock` representations.
     - Binds caption `InlineRun`s to `FigureBlock.caption` with normalized Russian text and run provenance.
     - Preserves all diagram text runs in `FigureBlock.runs` for full-text indexing and search.
     - Places `FigureBlock` in natural reading order by `bbox[1]`, ensuring top diagrams strictly precede bottom prose on the same page.
   - Updated `_should_merge_blocks`: Excludes `FigureBlock` entries from paragraph merging.
2. [`ingestion_service/ast/models.py`](file:///home/moses/tr_and_site/ingestion_service/ast/models.py):
