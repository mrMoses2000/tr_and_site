## 3. Scope

### Запрошено этапом
1. Устранить detached `asyncio.create_task` в обработке PDF.
2. Реализовать персистентную модель задач с состояниями `QUEUED`, `ACQUIRED`, `EXTRACTING`, `TRANSLATING`, `COMPILING`, `TESTING`, `DEPLOYED`, `FAILED`.
3. Реализовать lease-механизм: захват задачи воркером с таймаутом аренды, перехват просроченной аренды (expired lease reclaim), отклонение устаревшего воркера (`StaleLeaseError`).
4. Детерминированный порядок обработки: FIFO по `created_at ASC, id ASC`.
5. Ограничение попыток: превышение `max_attempts` переводит задачу в статус `FAILED`.
6. Дедупликация файлов по SHA-256 (`find_by_source_hash`).
7. Сохранение промежуточных чекпоинтов (`save_checkpoint`) и возобновление после имитации SIGTERM без повторения проверенных шагов.

### Выполнено
- Создан модуль `ingestion_service/jobs/repository.py`:
  - `JobRepository` с транзакционным SQLite-движком и индексами `idx_jobs_status_lease`, `idx_jobs_source_sha`.
  - Безопасные миграции колонок `source_sha256`, `worker_id`, `lease_expires_at`, `attempt_count`, `max_attempts`, `current_step`, `checkpoint_data`.
  - Атомарный `acquire_next_job` с проверкой просроченных lease и счетчика попыток.
  - Строгая валидация владения lease в `save_checkpoint` с возбуждением `StaleLeaseError`.
  - Поиск существующих книг по хешу содержимого `find_by_source_hash`.
- Создан модуль `ingestion_service/jobs/worker.py`:
  - `IngestionWorker` с обработчиками сигналов `SIGTERM` / `SIGINT` и циклом `run_loop`.
- Обновлен `ingestion_service/db.py` с сохранением 100% обратной совместимости для старых вызовов и добавлением новых миграций.
- Разработан тестовый сьют `ingestion_service/tests/test_p2_durable_jobs.py` из 7 тестов, подтвердивший RED -> GREEN.

## 7. Архитектурные решения

| Решение | Альтернативы | Почему выбрано | Положительное следствие | Отрицательное следствие |
|---|---|---|---|---|
| Lease-based concurrency в SQLite | Redis / Celery / RabbitMQ | Простота развертывания на локальном сервере Ubuntu без тяжелых внешних сервисов | Нулевые внешние зависимости, легкость бэкапа и транзакционность | Polling интервал (1-2 сек) |
| Защита от устаревшего воркера (`StaleLeaseError`) | Слепое применение апдейтов | Предотвращает перезапись результатов свежего воркера зомби-воркером | Гарантия непротиворечивости состояния и чекпоинтов | Требует передачи `worker_id` во все методы мутации |
| Дедупликация по SHA-256 файла | Дедупликация по названию книги | Имена файлов могут совпадать у разных книг или отличаться у одной и той же | 100% надежное определение повторных загрузок | Требует подсчета хеша при приеме |
